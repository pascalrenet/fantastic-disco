Make the kit total visible.

Use the statistical PCUM - Cumulation Condition to surface the combined value of LUMF subitems on the sales-kit header, without moving the commercial value away from the priced child items.

The idea in 15 seconds

A LUMF kit can be priced at component level while the header itself stays at zero. PCUM gives the header a readable, statistical total.

Child 30$110

$330

Why would you use PCUM?

In a sales kit, the customer sees one logical product, but pricing can live on the components. That is operationally correct, yet it can make the header look like it has no value. PCUM solves the presentation problem by calculating a cumulative value for the main item and its subitems.

1

Keep component pricing

The underlying child items retain their own net values, discounts and tax behavior. You are not replacing the normal pricing model.

2

Show a kit-level total

PCUM provides a convenient statistical amount at the LUMF header. It is ideal for display, review and downstream visibility.

3

Keep kits independent

The cumulative amount is calculated within each kit hierarchy. A discount applied to one kit's component changes that kit's PCUM, not the other kit.

What “Statistical” means here

The source configuration marks PCUM as statistical. In practical terms, the condition can carry a useful calculated amount without becoming the main commercial price of the header item. The component values remain visible and flow to billing in the example.

1. Add PCUM to the pricing procedure

Open the Set Pricing Procedures configuration activity and enhance the pricing procedure used by your sales-kit scenario. The source example places PCUM after tax-related calculations in a US pricing procedure.

Start in the configuration activity Set Pricing Procedures. In SAP S/4HANA Cloud Public Edition this is configuration activity ID 101117.

Think of formula 36 as the “roll-up” rule

SAP documentation for the LUMF scenario explicitly identifies PCUM as a statistical header price. The source configuration pairs PCUM with formula 36, whose role is to calculate a cumulative value across the main item and its subitems.

2. Prove the behavior with two kits

The strongest part of the example is the test design: create two instances of the same kit, then change only one component price. This makes it obvious whether PCUM is really calculated per kit hierarchy.

Two identical PR126 kits are shown. The second kit has a 50% discount on its first child item, making its cumulative amount different.

Kit 1 · Header item 10

$100 + $110 + $120 = $330

PCUM displays $330 on the kit header while the header's normal commercial net value remains zero in the example.

Kit 2 · Header item 50

$50 + $110 + $120 = $280

The first child receives a 50% discount, so this kit's PCUM falls independently to $280.

3. Follow the result into billing

The example then checks the billing document. The component lines retain their invoice values while the LUMF header carries zero net value. PCUM remains visible as a statistical pricing element on each header.

Billing items continue to carry the commercial values on the kit components: 100/110/120 for the first kit and 50/110/120 for the second.
First kit header: PCUM persists as 330 USD.
Second kit header: PCUM persists as 280 USD.

Why this is useful operationally

You get both views at once: detailed component-level pricing for calculation and billing, plus a concise kit-level value for people who think of the bundle as one product. That can make sales-order review, billing-document review and form/output design easier to understand.
